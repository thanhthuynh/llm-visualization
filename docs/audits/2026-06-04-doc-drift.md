## Drift detail: inline-style exceptions

### Claim

> "After migration, 16 inline `style={{...}}` blocks remain across 13 files. All are intentional."
> — `docs/tailwind-migration/cheat-sheet.md:104`

> "Sixteen inline-style exceptions remain — all documented in `docs/tailwind-migration/cheat-sheet.md` as CSS-var passthrough or template literals Tailwind can't express."
> — `README.md:121`

### Measured

`grep -rn "style={{" src --include="*.tsx"` returns **23 lines across 18 files**:

### Root cause

Plan 10 (landing page, commit `50b0996`) added 5 new files in `src/landing/` that use inline `style={{...}}` — `Hero.tsx`, `HeroPipelinePreview.tsx`, `LandingFooter.tsx`, `SceneCardGrid.tsx`, `SurfaceDeepPreview.tsx`. The cheat sheet was last revised before this commit landed and was never updated to reflect the new files.

### Methodology note

The cheat sheet's grep methodology has a minor bug: `src/components/Chip.tsx` uses `style={dynamicStyle}` (a pre-built variable object passed via single brace), which is functionally a CSS-var passthrough but does not match `style={{`. Chip is listed in the cheat sheet's Category 1 table but would not be found by the cheat sheet's stated grep pattern. The 23/18 count above is also a lower bound — the true "inline style props" total is 24/19 if Chip is included.

### Remediation

In this same session, the following will be updated:

- `cheat-sheet.md:104` — claim updated to `23 blocks across 18 files`
- `README.md:121` — claim updated to `Twenty-three inline-style exceptions`
- The cheat sheet's Category-1/2/3 tables are NOT updated in this audit — the 5 new landing files have not been individually categorized yet. A separate pass should triage each as legitimate exception vs migration candidate.
