### Deferred — `color-contrast` (serious, 9 occurrences)

Every scene produces at least one `color-contrast` violation. The most common offender is accent-colored small text against the dark surface, e.g.:

| Element | Foreground | Background | Ratio | WCAG AA target |
|---|---|---|---|---|
| Predict accent badge `71%` (15px) | `#9d4edd` | `#16161f` | 3.9:1 | 4.5:1 |

The 15px font falls into the WCAG AA "regular text" bucket which demands 4.5:1. The accent palette was chosen for visual identity; bringing every accent above 4.5:1 against `#16161f` requires brand-level decisions:

**Options for the brand-level follow-up:**

1. **Lighten the accent tokens** (e.g., predict from `#9d4edd` to ~`#b876ee`). Affects all 7 accent colors. Visual identity shifts.
2. **Restrict accent text to ≥18pt regular or ≥14pt bold** (WCAG AA "large text" needs only 3:1). Keep current colors but never use them on body-sized text.
3. **Use accents for backgrounds + borders only**, never foreground text.

**Recommendation:** Option 2 — preserves the brand palette while honoring contrast. Audit every accent-text use-site and bump to ≥18pt or ≥14pt bold.

This is tracked as a separate plan; the test infrastructure here will gate any future regressions in *new* contrast violations (the `DEFERRED` set in `e2e/a11y.spec.ts` can be tightened to specific element selectors when the brand fix lands).

## Layer 3 — Manual screen-reader walkthrough

**Deferred to operator** (this audit's automated portion can't drive a screen reader).

The script below should be performed at least once. Findings get appended back to this doc.

### VoiceOver walkthrough checklist (macOS)

1. Start dev server: `npm run dev` → open `http://localhost:5173`
2. Enable VoiceOver: `Cmd+F5`
3. For each scene (via rail or `ArrowDown`), capture:

```markdown
### {SceneName} — VoiceOver findings (YYYY-MM-DD)

- [ ] **Reading order** — logical top→bottom? Any sections out of order?
- [ ] **Landmarks** — `main`, scene `section`s, and per-scene `nav` all announced with unique labels?
- [ ] **Heading jumps** — pressing `VO+Cmd+H` lands on the scene title?
- [ ] **Interactive elements** — every button/link has an audible name? `aria-pressed` toggles announced?
- [ ] **Dynamic content** — Chip selections, prompt edits, depth toggles announce changes? (look for `aria-live` regions)
- [ ] **Skip link** — `Tab` from page top focuses "Skip to content" and activating it lands on `#prompt`?
- **Issues found:** {list with file refs or "none"}
```

### NVDA walkthrough — deferred

Repeat the same checklist on Windows + NVDA when a Windows environment is available. The scenes use no platform-specific ARIA, so coverage should be similar.
